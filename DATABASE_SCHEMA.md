# Balsathi AI — Current Prisma Schema

## Status and conventions

The active schema in `prisma/schema.prisma` uses SQLite. The first SQLite migration is `prisma/migrations/20261015000000_init_sqlite/migration.sql`. PostgreSQL migration files are preserved separately under `prisma/postgresql-migrations-legacy/`; they are not part of the active SQLite migration history.

- IDs are text strings generated by Prisma `cuid()` unless supplied by a controlled seed or migration.
- Calendar dates and timestamps use SQLite `DATETIME` storage and Prisma `DateTime` values. API date serialization uses ISO strings.
- Domain enum-like values are stored as strings and validated by application code.
- Lists and structured values are stored as Prisma `Json` fields. Validate shape before use.
- Foreign keys and uniqueness constraints are represented in the Prisma schema and enabled by Prisma's SQLite connector.

## Models

The active schema includes centers, users, guardians, children and guardian links, observations, milestone definitions and assessments, growth measurements, development assessments, follow-ups, recommendations, messages, chat logs, ML predictions, idempotency records, and audit logs. Refer to `prisma/schema.prisma` for the exact fields, relations, indexes, and deletion behavior.

Important scoped relationships:

- Workers are linked to centers through JSON `User.centerIds` and assigned children through `Child.assignedWorkerId`.
- Parents access children through `ChildGuardian` links and their linked user identity.
- Administrators are scoped by `centerIds` or district-level policy.
- Observation authors, milestone assessors, and audit actors reference stored users.

SQLite does not enforce the domain's role/locale string unions or the internal shape of all JSON columns. API Zod schemas and service-layer checks must validate these values. Do not treat a valid foreign key as sufficient authorization.

## Sessions and assistant replies

SQLite login checks a bcrypt password hash and session requests reload active user, role, locale, and center scope from the database. Session tokens are still stateless and cannot be revoked individually before expiration. Assistant replies are not stored as durable conversation history by the supported flows.

## Migration and data safety

To create the current SQLite schema:

```sh
npm run db:generate
npm run db:migrate:deploy
```

This creates or updates the SQLite file selected by `DATABASE_URL`, default `file:./dev.db` relative to `prisma/schema.prisma`. It does **not** copy records from a PostgreSQL database. PostgreSQL-to-SQLite record migration requires a separately planned, verified export/import, including date normalization, JSON conversion, ID/relationship integrity, and reconciliation counts. Keep the PostgreSQL source and backups until reconciliation is complete.

SQLite data files are local runtime artifacts and are ignored by Git. Backups and restore drills must be handled operationally; schema migration history is not a data backup.
